# 管理界面审视与渐进演化

2026-10-23。范围为内置概览、账号、设置页。使用源码、真实 Rust `ui_demo`、虚构账号和本地假上游验证；
未访问生产账号。设计案例与访问来源见 [DESIGN_REFERENCES.md](DESIGN_REFERENCES.md)，
指标公式和历史限制见 [METRICS.md](METRICS.md)。

## 产品尺度

当前交付保留三页、自包含 HTML、文本节点渲染和 CSP 哈希；后续源码组织建议见下文。
个人网关应让人容易知道“我在看什么、何时的数据、
接下来查哪条请求”，而不是需要先学习一套监控平台。

Grafana 提供时间范围、指标语义与钻取思路；整体交互同时参考 Linear 的信息层次、
Stripe Workbench 的请求调查，以及 Vercel Logs 的连续巡阅与明确刷新。
没有引入仪表盘布局编辑器、查询语言、运行时 CDN 或前端构建依赖。

## 已落实的调查路径

**一个范围。** 时间、账号、请求模型、密钥标签、实例是共同范围。概况、分布、趋势和请求使用同一对
绝对 `from/to`，避免几次 rolling range 各自取当前时间。概况与趋势共用一次带 buckets 的 summary 查询，
不为同一窗口扫描数据库两遍。分组只影响分布表，图表粒度只影响分桶。

**再缩小请求。** 结果、错误来源、档位、错误码和重试是列表内条件，不改上方分母。
常用结果筛选直接可见，其余按需展开；已生效条件始终有文字摘要，手机也能查看和清除。
模型、密钥和实例采用直接文本匹配；分布表的账号/模型等可点击应用为共同条件。
不提供嵌套布尔条件构建器。

**数字有含义。** 六组安静摘要显示请求量、失败率、流式首输出、生成速度估算、Token 和参考费用。
取消、未完成、预热分别可查；首输出 p50/p90 与生成速度附样本数，不把缺样本填成零。
有请求但没有任何 usage 样本时，Token 显示未报告；混合样本只累计已报告部分，并显示样本数。
输入缓存指供应商报告的缓存读 Token 占比，不是网关响应缓存命中率；费用不是实际账单。
取消不再作为服务失败着色，没有凭空设定“超过 5% 就红”的统一阈值。

**一张可钻取的图。** 请求、Token、费用切换使用单一尺度。图表覆盖查询范围内所有桶，
包括滚动 24 小时的首尾两个部分小时；不会丢掉最早的一段。部分桶用虚线，时间桶可聚焦并由键盘选择。
点击后固定共同范围、只收窄请求列表的时间，保留其余条件，并提供“返回整个范围”。
固定范围的实际起止在手机上也可见。
范围变化后，旧图表会标明等待更新，点击事件也即时核验范围；输入防抖期间同样不会钻入旧时间。
点击全局请求/失败/取消数会清除局部时间桶，列表与所点数字的分母一致。

**实时状态单列。** 管理密钥可看当前转发占用/上限、WS 连接数、进程累计的容量拒绝数。
用一行轻量文字标明这是当前进程状态，不受历史范围筛选；没有采集入口 RPS、CPU 或排队耗时就不绘制。

**所有请求有详情。** 成功、失败、预热都可查看元数据，不要求保存完整请求或模型回答。
时间、记录 ID、账号/密钥/实例、模型/实际模型、档位、首输出、耗时、Token、费用、重试/换号与已有尝试链
汇合在同一个详情面板。非流请求不把响应头时间冒充首输出。

详情支持当前列表中的上一条/下一条、复制 JSON、复制带固定范围的链接、按记录 ID 查找。
ID 搜索接受大小写，未找到的结果会保留在查找位置。深链可独立于当前列表打开，列表稍后到达时也更新导航。
保留现有对话框机制和关闭后焦点/滚动恢复；尚无必要为侧栏外形重写全局弹窗体系。
请求表保留 table 语义，时间单元格内有实际按钮，整行点击是便利操作。

## 刷新与异步状态

- 查询使用递增序号、查询签名和当前登录密钥判断响应是否仍有效。旧成功、旧错误都不能覆盖新条件；
  `allSettled` 延迟呈现的错误在实际显示时再检查。全局更新失败说明保留了最近一次结果。
- 翻页使用完整记录 ID 游标，不因同毫秒记录而遗漏，不再依赖易被迟到写入移动的 offset。
  `next_before_id` 决定是否还有下一页，total 仍可能随请求完成而改变。
- 浏览第二页或选中图表时段时，自动刷新保留整个查询上下文；手动刷新重新读取第一页。
  固定范围可持续重新读取这个窗口，选择“返回最近”才恢复随时间滚动。
- 详情请求绑定面板代次、记录 ID 和登录身份。关闭或切到下一条后，旧详情不能填入新面板；
  明细加载期间禁用复制，明细过期时保留请求概要。
- 额度刷新保留各项最近成功结果，失败不会统一伪装成“没有账号”。额度是独立的当前上游快照，
  明确不属于上方历史请求范围。记录器丢弃/写入错误显示进程累计值，不伪造窗口完整率。
- 账号页分别维护账号、额度、重置卡的成功快照。短暂故障保留旧值并说明最近成功时间，
  权限不足或接口不可用则清除对应快照并明确原因；首次失败不声称已有旧数据。
  退出清除账号缓存，旧登录的迟到401/403不会退出或降级新登录。

没有用前端筛选充当权限隔离。普通密钥目前可读取服务级 usage；管理能力仍由后端授权。
进入多租户场景前必须先设计服务端 scope，不能只加角色标签。

## 布局与实测

请求紧接趋势，账号额度和分布放在其后；ID 查找和低频请求筛选按需展开。
桌面使用一行摘要，手机使用两行三列；长密钥/模型省略显示，完整值在详情保留。
手机详情标题独占一行，复制/关闭/上下条操作具有 40px 高度。

实际 demo 在 1280px 下，请求表宽度与容器同为 1230px，耗时列在可见范围内。
加入实时状态后的 375px 窄屏页面宽度保持 375px；请求区约在 y=717，第一条约在 y=811。
早期版本的手机请求区约在 y=1498，主要被额度矩阵挡在前面。
这些是同一模拟浏览器中的布局观察，不能代替真实移动设备与屏幕阅读器验收。

已验证：

- `node scripts/ui-state-check.cjs`：迟到成功/错误、登录变化、共享时间与筛选、小时粒度不改变 7 天窗口、
  25 个部分/完整时间桶、ID 翻页、旧页不能拼入新筛选、浏览历史时整个范围保持稳定、旧范围钻取与无 usage 样本。
- 现有 Rust UI 测试：自包含资源/CSP 哈希、三页共享块字节一致。
- 真实 demo：桌面/手机、成功和失败详情、上下条、Esc 返回、全局/局部筛选、图表钻取、ID 查找和深链。
- 人为扣住两次详情 HTTP 响应，先放 B 再放 A；面板只含 B 的标记，复制已启用，无 A 的残留。
- 深链刷新后详情正确显示“3 / 50 · 当前列表”，上下条可用；概况与趋势只发出一次 summary 请求。
- 演示中的 HTML 形状账号/模型继续作为文字显示；没有增加 HTML 字符串渲染入口。
- `node scripts/accounts-state-check.cjs` 与375px浏览器：部分503保留快照，403/404分别显示不可用，
  退出与重新登录不残留旧身份数据，失败后恢复正常；共享请求函数另覆盖迟到401/403的身份隔离。

设置页刷新与密钥操作保留有效/无效原始输入；版本冲突后再次检查展示最新服务器值与草稿差异。
保存成功但刷新失败时仍保留草稿并明确写入已完成，下一次编辑不再使用过期基线判断是否修改。
独立 Node 回归及浏览器验证见 [TESTING.md](TESTING.md)，交付记录见 [process.md](process.md)。

账号页通过列表标题旁的“添加账号”原地展开设备码登录，粘贴JSON再按需展开，文件导入保留直接入口。
空账号同样有可操作入口。设备码开始与轮询绑定流程代次和登录身份，停止或退出后清除代码、链接、
倒计时与相关请求；退出也清除粘贴的凭据。页面上的“停止等待”不承诺取消服务器正在进行的授权。
桌面及375px验证了展开/收起焦点、失败重试、停止后的迟到状态、同密钥退出重登后的迟到代码与空态布局。

最后一轮连续浏览复核发现：打开详情前已发出的列表刷新，仍可能在详情打开后返回并重建行，
使关闭详情时保存的原按钮失效。现在按原记录的行标识重挂返回焦点；记录已退出列表时回到请求结果筛选，
ID查找入口与详情内上下条浏览仍保留原返回位置。浏览器先复现旧行为，再用延迟的真实demo列表响应确认修复；
同条保留与被筛掉两种情况均通过，Node回归执行实际渲染与关闭函数，没有引入浏览器CI。

## 源码组织与框架选择（补充评估）

在`8a44d0e`上复核实际源码，并由独立子代理审阅后，建议继续静态嵌入Rust二进制，
前端源码则逐步转为组件与状态模块。首选用Svelte + TypeScript + Vite验证一块真实交互；
这是一项后续建议，本次没有安装依赖、迁移页面或测量浏览器性能。

### 当前成本

实际有三份HTML，概览121,004 bytes / 1,085行、账号72,183 bytes / 688行、设置62,503 bytes / 625行。
三页合计约250 KiB，每页重复约32 KiB公共CSS/JS；体积本身不大，复制维护已经需要
`ui.rs`中的`shared_blocks_identical`测试保证同步。`include_str!`只要求交付时有静态文件，
不要求这些文件也是手写源码。

`ui.html`的`renderRecords`会清空并重建全部已加载行；`loadRecords`每次追加50条，
累计行数没有总量上限。翻页越深，重复构建的DOM越多，开着详情时还要重新定位已经替换的返回按钮。
当前已有焦点/滚动恢复、模态栈、请求代次、身份与查询签名、草稿修订等一整套手工状态管理。
这些是可定位的维护成本，不等于已经测得卡顿。

现有首屏50条、15秒自动刷新、服务端聚合和一张SVG图，仍是原生DOM适合承载的负载。
框架不会自动加快SQLite查询，也不会消除迟到响应、登录变化和配置版本冲突。
收益应体现在保留稳定节点、明确状态归属、减少重复代码，以及让组件和交互更容易修改。
布局、留白、信息层次与动效仍要单独设计，沿用当前设计token和定制CSS即可。

### 技术取舍

- **原生模块化**可以先消除共享代码复制，并让测试直接导入函数；若UI基本稳定，这是足够的方案。
  若继续扩展调查路径、账号能力与编辑流程，还会持续自建组件更新和生命周期机制。
- **Svelte + TypeScript + Vite**是当前优先候选：模板接近HTML、组件样式就近组织，
  以请求ID作为key保留行身份，状态变化更新相应视图。保留业务竞态守卫，不把响应式当作并发保证。
  Vite用于开发与构建，不要求部署Node服务；当前三条页面路径也不要求改成SPA。
- **Vue + Vite**同样适合，若维护者更熟悉Vue，应优先考虑熟悉度；使用构建期编译模板。
  Preact适合已有JSX偏好的情况。React能胜任，但目前没有必须依赖其生态的功能；
  无需同时引入SSR、全局状态库、路由框架或整套组件库。

单HTML是产物选择，单二进制是部署选择。可以从模块源码构建三份自包含HTML；
也可以把少量带内容哈希的共享JS/CSS一同嵌入Rust，由同源静态路由提供。
后者可复用缓存，但不能只看缓存收益而忽略构建与CSP适配成本；不为坚持每页单文件堆叠定制插件。
建议将生成物入库，前端变更时重建并检查一致性，使普通Cargo构建仍不需要Node。

### 一块真实交互验证

1. 提取查询/指标格式化与异步状态模块，让现有必要检查直接导入实际代码，逐步移除按字符串截取HTML函数的方式。
2. 用请求列表及详情做局部对照原型。覆盖50条首屏、追加历史、迟到刷新时打开详情、Esc返回、
   上下条和深链；验证稳定行身份是否减少现有焦点补偿。迁移区域由一个渲染器拥有，避免双方修改同一DOM。
3. 在同一浏览器、相同数据和API条件下比较产物体积、首次可交互、50/500/2,000条时的追加/刷新耗时、
   长任务与DOM数量；分开观察网络等待和渲染成本。这些是对照负载，不是新增CI性能门槛。
   keyed更新不会限制累计DOM数量，长列表若确有成本，再选择有界分页或虚拟化。
4. 行为更清楚且成本可接受后，沿同一种方案迁移其余页面，避免长期维护两套渲染机制。
   保留草稿、迟到成功/错误、身份切换等已有回归和少量真实浏览器验证；不为迁移扩大通用测试框架。

迁移需同时处理现有资源约束：`ui.rs::inline_blocks`只识别裸`<script>`/`<style>`，
常规Vite模块脚本和外部资源不能直接套用现有哈希提取。当前测试还禁用`innerHTML`字面量，
而编译器可能用HTML解析创建可信静态模板；应核验生成物和实际CSP，将检查聚焦于
动态账号/模型/错误内容始终作为文本、脚本来源受限且无`unsafe-eval`、无运行时CDN依赖。
不能仅删除失败的字符串检查，也不要求生成代码保持旧手写源码形状。

## 下一步只做有证据的改进

1. **真实运行现况。** 观察实际使用后再决定是否需要趋势采样，当前保留轻量快照。
2. **源码与连续阅读。** 按上方方案验证组件化的维护收益，比较真实交互和渲染成本；
   再决定是否需要虚拟化或侧栏。
3. **供应商能力。** 第二种真实适配器需要出现后再设计 provider/route 字段；OAuth、套餐窗口、重置卡保持适配器能力。
4. **计量缺口。** 排队、连接、完整入口耗时、逐 Token 时间需要实际采集；目前不画假瀑布图或 TPOT。

性能基线与限制见 [PERFORMANCE.md](PERFORMANCE.md)。本轮不声称真实供应商容量、完整 WCAG、
多租户隔离或长时间生产运行已经验证。

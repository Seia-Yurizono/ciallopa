# 管理界面

界面围绕“发现异常 → 缩小范围 → 查看请求 → 返回原位置”组织。概览、账号和设置保持三个简单入口，
由 Rust 静态嵌入交付，部署无需前端运行时。

## 调查范围

时间、账号、模型、客户端密钥和实例是共享范围，作用于概况、趋势与请求列表。
问题分组、原因及“更多筛选”里的结果、错误来源、档位、错误码和重试条件仅缩小请求列表，不悄悄改变概况的分母。
范围标签说明作用对象；清除单个条件只改变该条件，清空操作保留各自作用域。

点击概况或趋势桶会带着相应范围进入请求。URL 保存可分享的调查条件；分享时固定时间边界，
不承诺重新打开链接后记录仍在保留期内。按完整记录 ID 查找与普通列表筛选分开。
列表采用 ID 游标追加，固定时间窗不等于数据库快照：迟到完成的请求仍可能进入该时间窗。

## 请求问题分组

请求列表顶部是问题分组：全部 / 报错 / 上游出错 / 没答完 / 本地拒绝，每个带数量；
选中分组后第二行列出原因子分组（报错：额度、限流、请求内容、上游、网络代理、网关、流中断；
上游出错：未救回、已救回；没答完：客户端断开、需重连、上游截断、内容过滤、未确认结束；本地拒绝：各类上限）。
分组下的说明条只陈述口径，例如“报错计入失败率”“没答完不计入失败率”“已救回 X · 未救回 Y”，
不新增比率。分组和原因的判定只在后端完成，界面只显示后端给出的 `problem`、`cause`、`rescued` 与 `next`。
全部默认排除预热，“更多筛选”里的“含预热”可打开。

账号、模型、密钥三个小下拉与共享范围同步；结果、失败原因、错误来源、档位、错误码、重试与旧错误条件
收在请求标题栏的“更多筛选”里，窄屏也能直接找到入口；后端参数保持可用，旧链接仍能打开。
原“未完成”改名为具体原因：客户端断开、上游截断、未确认结束。
本地拒绝在设置了账号、模型或仅请求有的条件时禁用，因为拒绝发生在这些信息确定之前。

## 按会话查看

“更多筛选”里的“会话 ID”接受完整 Codex 会话 ID 或其中连续至少 8 位（任意位置，不区分大小写），回车应用；
后端把唯一匹配的片段换成完整 ID，界面随之更新输入框和 URL（参数 `fthread`）。片段对应多个会话时列表显示
“这段 ID 对应多个会话”，不当作更新失败。生效时显示可移除的“会话：…尾 8 位”标签（悬停看完整 ID），
与问题分组、原因、“更多筛选”条件和共享范围的账号、模型、密钥、实例叠加，分组数量同样按会话计算。
会话不受时间范围限制，查整个保留期，列表数量后注明“不限时间”；在趋势里选中的时间段仍然生效。
本地拒绝没有会话信息，选择会话会离开本地拒绝视图。

请求详情的“会话”一栏显示 ID 尾 8 位（UUIDv7 开头是时间，相邻会话开头相同），悬停看完整 ID，
“复制”复制完整 ID；“只看这个会话”清除请求条件、选中时间段和共享范围的账号、模型、密钥、实例（中途换号的会话也能看全），
列出该会话的全部请求；在“更多筛选”里手动粘贴会话 ID 不改变共享范围。
“轮次”单独一行。

每行给出最多两个“下一步”按钮（窄屏只显示第一个），详情顶部的结论块说明发生了什么、是否计入失败率，
并重复这些按钮。下一步只跳转或打开已有视图：刷新额度定位到账号额度的普通刷新按钮，
看账号、账号状态跳到账号页，检查出口和限流设置跳到设置页，尝试链打开详情并滚到尝试过程；从不使用重置卡。
被重试或换号救回的请求标“已救回”，并写明“重试 N 次后成功”或“换号 A → B 后成功”。
窄屏下分组与原因横向滚动，不换行。

未知用量与明确零分开显示，费用是价格表估算。首输出、速度与成功率使用各自样本，
不能把预热、取消或缺测值混入相同分母。完整定义见 [METRICS.md](METRICS.md)。

## 请求详情

成功与失败请求都可查看记录信息；错误详情可能受权限或保留期限制。
详情提供上下条、复制 JSON、复制链接与关闭，返回列表时保留滚动位置和可用焦点。
响应头与正文保留可读高度，长内容在弹窗内滚动；到达末尾后不会带动背景列表滚走。
读取失败允许原位重试；已过期详情继续显示概要，不把 404 当作可以无限重试的网络故障。
这里的重试只重新读取详情，不重新发送模型请求或执行工具。

详情读取绑定当前记录、面板代次和登录身份。关闭、切换记录或退出后，迟到响应不能覆盖新内容。
键盘操作须能到达筛选、详情及恢复按钮；关闭返回合理焦点，弹窗操作不依赖鼠标悬停。
小屏保持内容次序与可触达的按钮，不靠缩小文字塞入桌面布局。

## 刷新与编辑

概览的内存区默认显示 RSS、缓冲占用/上限及比例、WS 连接/上限和读取时间；缓冲或 WS 上限为 0 时明确显示“不限”。
“展开指标与趋势”一步显示原有峰值、jemalloc 分配/驻留、WS 缓冲及内存历史趋势，原生展开控件支持 Enter/Space；
普通与自动刷新保持开合选择和控件焦点。缓冲占用 ≥80%、WS 连接达到上限时，折叠摘要也显示文字提示，
不额外推断健康状态。RSS 缺测标未知；无管理权限或内存加载失败时仍隐藏整个区域。

- 概况和趋势共用一次 summary 请求，避免同范围重复扫描。
- 自动刷新间隔在顶栏开关旁选择（5/15/30/60 秒，默认 15），保存在本浏览器；改动立即重启计时，
  标签页不可见或有对话框打开时暂停。
- 请求列表按记录 ID 复用行；未变的行不重建，追加、删除、重排和空态切换保留正确焦点。
- 账号/额度读取的短暂失败保留最近成功快照并显示其时间；失权或不可用不继续伪装成当前数据。
- 上游前的 Cloudflare 拦截或质询本机出口（如 1010）时，概览显示红色横幅（代码、最近时间、次数，悬停看 cf-ray 和账号），直到下一次正常的上游响应；这类请求不换号、不冷却账号。
- 设置草稿不会被后台刷新覆盖；版本冲突给出差异，保存成功后刷新失败与保存失败分开显示。
- 放弃草稿需在确认弹窗中明确选择；默认聚焦取消，没有确认倒计时。取消保留草稿，确认后载入最新配置并恢复字段焦点。
- 设置项显示说明与默认值；有固定取值的选项（如选号策略）以单选列表逐项说明。
- 旧登录的迟到 401/403 不能清除新登录；退出会清空只属于当前身份的敏感显示。

设备码登录的“停止等待”只停止页面轮询，不撤销服务端已开始的授权；文案和状态保持这个区别。

## 实现与设计依据

当前使用原生 HTML/CSS/JavaScript。请求列表已采用 keyed 行复用；局部实验表明，常见的未变刷新和
追加无需引入框架。Svelte 在大量单元格同时改变时有优势，但该实验不代表整站表单、权限或网络状态。
以后以实际维护成本决定组件化范围，保留静态嵌入交付和 CSP 约束。

整体层次借鉴 [Linear 的筛选](https://linear.app/docs/filters)、
[Stripe Workbench](https://docs.stripe.com/workbench) 和 [Vercel Runtime Logs](https://vercel.com/docs/logs/runtime)：
请求列表是主体，细节按任务展开，URL 与焦点保留调查上下文。
[Grafana 面板链接](https://grafana.com/docs/grafana/latest/panels-visualizations/configure-data-links/)
主要用于指标口径和钻取思路，不作为整页视觉模板。

交互修改用现有 Node 状态回归与真实浏览器验证，覆盖桌面、375px、小型失败/空态和键盘流程；
DOM stub 不证明真实布局或完整可访问性。执行方法见 [TESTING.md](TESTING.md)。

持续改进人体工学和简洁美观度时，采用[手动爬坡流程](research/UI_HILL_CLIMBING.md)：
固定任务和可比场景，每轮验证一个主要假设，记录前后证据及保留或回退的理由。
已完成实验的效果、代价和证据见[2026-10-31 结果报告](research/UI_HILL_CLIMBING_RESULTS.md)。

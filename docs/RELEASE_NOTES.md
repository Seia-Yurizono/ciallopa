# Release notes — v0.4.1

本版本基于 v0.4.0：停止服务从最长约 70 秒缩短到几秒，被打断的回合由 Codex 自动重放；管理页面整理为「账号中心」，额度相关内容集中到账号页，并改进了手机端和按钮层级。usage 数据库 schema 不变（仍为 v15）。

**快速停止**

- 收到 SIGTERM/SIGINT 后，正在进行的响应最多等待 `shutdown_drain_secs` 秒（新增顶层配置，默认 5，可设 0–60，可在设置页热更新，在收到停止信号时读取）。此前固定等待 60 秒。
- 到时仍未结束的 Responses SSE 流或 WebSocket 回合按固定顺序收尾：先转发上游已在途的数据（最多 0.5 秒），再发送可重试的 `response.failed`（`code: gateway_restarting`，`retry-after: 2`），最后正常结束响应体或以 1001 关闭。排空期间新发起的 WS 回合也会收到同样的事件。Codex 0.167.1 会在 2 秒后按历史重建并重放该回合，已完成的工具调用不会重复执行。
- 排空期间被拒绝的请求，`Retry-After` 改为 2。停止日志会记录 `drain_secs`，并每 10 秒输出一行仍在排空的提示。
- Docker `stop_grace_period` 和 systemd `TimeoutStopSec` 从 75 秒降到 20 秒（5 秒排空 + 3 秒关闭 + 5 秒 usage 落盘 + 2 秒运行时退出）。若调大 `shutdown_drain_secs`，请让两者至少为排空时间加 15 秒。
- 修复被截断的响应体再次轮询已完成的强制结束任务时会 panic 的问题。

**账号中心**

- 首页分为「用量」和「系统情况」两个标签。「系统情况」收纳内存和 Cloudflare 拦截提示等，有告警时标签上显示数量；「用量」显示所有账号合计的 5h / 周剩余额度，并可跳转到账号页。
- 每个账号的额度都放到账号页：每行显示 5h 和周剩余百分比、30 天周额度变化小图、重置卡数量；展开一行（手机上为底部弹层）可查看额度记录、调度设置、重置卡和操作。
- 「额度记录 · 30 天」一次只画一个窗口：同时有两个窗口的账号可在「周 | 5h」之间切换（默认周，本次浏览期间记住选择），只有周窗口的账号只显示周。每个周期的容量画成一条阶梯线，每次重置标一个空心点，悬停、方向键或轻点可查看重置类型、时间、容量范围、API 价格和用卡情况。两个周期之间没有数据时用淡色虚线连接，不凭空补值。纵轴按典型周期取上限，个别异常周期不会把其余数据压扁。原先的 API 价格直方图已移除。
- 窗口按 `window_minutes` 区分（300 为 5h，10080 为周），不再按上游的 primary / secondary 位置判断。因此 Pro 账号只显示周额度，不会出现多余的 5h；首页合计的 5h 额度也不计入 Pro 账号。
- `GET /usage/v1/quota/history` 的 `account` 参数改为可选，不传时返回全部有记录的账号；结果中的账号 id 为当前 id，旧别名下记录的历史也会映射回来。账号页只需请求一次即可画出所有行。

**手机端与按钮**

- 适配 iPhone 常见宽度（含 402 px）和横屏，处理刘海和底部安全区；触屏下顶栏、工具栏和各类按钮的点击区域至少 44 px，外观紧凑的控件通过透明扩展区补足。
- 按钮层级统一：同一屏只有一个实心主按钮；带文字的操作都有边框，开关类按钮按下时有明显状态；只有纯图标按钮和账号行的「详情」不加边框；删除用红色描边，确认框里才用实心红。「重新扫描目录」「刷新全部额度」等此前看起来像普通文字的按钮现在有了按钮样式。
- 「添加账号」改为展开开关：再点一次收起，展开时变为按下态并带 ▴，面板内「开始设备码登录」是唯一的实心按钮；按 Esc 或「收起」关闭面板，焦点回到「添加账号」。
- 概览卡片里可点击的小号数字平时带点状下划线；不可点击的计数不再画成胶囊。
- 页面样式全部通过 CSSOM 设置，不使用内联 `style` 属性，在严格的 CSP（不允许 `unsafe-inline`）下没有报错。

**升级**

- 配置文件无需修改，`shutdown_drain_secs` 不设置时为 5 秒。usage 数据库不迁移。
- 使用自带的 compose 文件或 systemd 单元时，新的 20 秒停止超时随文件更新；自行维护的部署请同步调整。
- 发布后，`latest` 和 `0.4` 指向 0.4.1。按[容器清理策略](https://github.com/Seia-Yurizono/ciallopa/blob/main/docs/CONTAINER_CLEANUP.md)，GHCR 只保留最新的两个标签名，固定在 `0.4.0` 的部署之后可能无法再拉取该镜像，请先改为 `0.4.1` 或 `0.4`，见[部署指南](https://github.com/Seia-Yurizono/ciallopa/blob/main/docs/DEPLOYMENT.md#image-tags-and-upgrades)。

**验证**

- 本地 workspace 测试 560 项全部通过（含快速停止的 SSE / WS 截断顺序、可重试事件和 1001 关闭，以及历史接口的 id 映射），loadbench 示例 5 项通过。严格 Clippy、格式检查、发布与容器脚本自测，以及 UI、设置、账号和请求观测四项 Node 检查均已通过；账号页的开关、Esc、焦点和「每个状态一个实心按钮」由 Node 检查断言。指纹检查（fp-check）通过。安装包与容器的冒烟测试在标签工作流中运行。
- 依赖锁文件只更新了本仓库各 crate 的版本号，第三方依赖没有变化。验证全部使用合成数据和本地模拟上游，未调用真实模型上游。

本次从 0.6.0 升级到 0.6.1，修复重置卡消费被重复归因的问题，并补强额度分类和管理界面的回归验证。

**重置卡归因修复**

- 同一次成功消费在每个额度窗口最多归因一次，避免后续用量下降再次生成用卡重置事件和已关闭周期记录。
- 保留双窗口分别归因，以及重置时间先更新、用量随后下降的分阶段观测支持。数据库重开或历史清理不会重新激活已经关联的消费，新消费仍可正常归因。

**验证改进**

- 增加额度分类不变量、重复归因、事务回滚和数据库迁移回归测试。
- 增加真实浏览器流程检查，覆盖登录、筛选与迟到响应、详情焦点恢复、名称安全显示及手机宽度；通过故障注入确认检查能够发现错误。

**升级说明**

本次将用量数据库升级到 schema v21，新增两个可空观察 ID 字段，用于记录消费在两个窗口中的归因。升级前请备份配置和用量数据库；回退应使用升级前备份，不承诺旧版本兼容升级后的数据库。

迁移不推测历史事件归属，也不重写历史统计，因此旧的重复记录不会自动消除。升级前仍处于匹配时段的成功消费，升级后可能在每个窗口额外关联一次。本次未改变按重置时间划分额度周期的方式。

安装与备份方法见[部署指南](https://github.com/Seia-Yurizono/ciallopa/blob/v0.6.1/docs/DEPLOYMENT.md#image-tags-and-upgrades)。

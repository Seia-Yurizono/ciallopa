本版本修掉额度周期被拆成多条短记录的问题：按请求开始顺序记下、晚到的过期快照不再当作当前状态；同一窗口内不到 5 个百分点的小回落不再记成额度变化；额度变化本身也不再单独写一条周期记录。手动卡之后的已用额度不再被新窗口开头的请求抬高。界面会把同一起点的旧记录合并显示，标「含合并记录」。没有数据库迁移，已经写下的多余记录可用「重置估算」清掉。

**过期快照不再当作当前状态**

- 请求的记录 id 在开始时领取，配额头要等请求结束才写入。一条更早开始、更晚结束的请求（另一会话里的长对话，或重置卡刚用掉之前发出的请求）以前会被当成最新快照。
- 重置卡用过之后，旧窗口的迟到响应会再关一次周期，并把新窗口开头的请求算进已用额度（用户看到的「手动卡」周期已用远高于容量，就是这个原因）。
- 现在：id 比当前最新快照更旧的记录仍留给估算用，但不再参与分类，也不会更新当前缓存。

**同一窗口内的小回落不再是额度变化**

- 以前只要百分比掉了至少 0.5、且不超过 5 个点，即使 `resets_at` 没动，也会记成额度变化。整数的响应头和带小数的 `/wham/usage`、以及乱序结束的请求，都容易触发。
- 现在同一窗口内的回落必须至少 5 个点，或者从 10% 以上减半，才记额度变化。更小的回落忽略。

**额度变化不再写周期行**

- 周期按 `resets_at` 对齐。以前每次额度变化都会再写一行，起点和正在进行的周期相同，于是同一天出现多条「11-11→11-11」的短记录，已用额度是完整周期的前缀。
- 现在额度变化只记事件，周期继续走下去。

**界面合并旧记录，不迁移**

- 同一个起点只显示一行：进行中的周期，或者第一次把它结束的重置。被合并的记录写在明细「已合并」，行上标「含合并记录」。
- 不改 usage 数据库 schema，也不重算历史周期。已经写下的多余记录可用「重置估算」归档，也会随保留期清掉。
- 升级前请停止服务并备份 usage 数据库及相关 WAL 文件。安装与镜像标签说明见[部署指南](https://github.com/Seia-Yurizono/ciallopa/blob/main/docs/DEPLOYMENT.md#image-tags-and-upgrades)。
- 分类顺序、小回落和额度变化各先用失败的测试复现，全部使用合成数据。合并后的完整本地回归 610 项通过，严格 Clippy、Node 状态检查、lock-check、cargo audit 和指纹检查通过；桌面 1280 与 402×874 手机尺寸、浅色和深色截图已检查（含用新界面直接看 v0.5.3 写下的旧行）。

本版本调整额度周期的展示方式，并把点数和额度彻底分开计算与展示：蓝色块就是估算容量，已用额度用另一种颜色画在里面；额度用满后另扣的点数单独列出，不再计入额度、容量和周期 API 价格。用词上，「额度」指订阅包含的额度（单位 credits），「点数」指另外购买的点数。

**额度周期展示**

- 每个周期一行，蓝色块的长度就是估算容量（所有行共用一条 credits 刻度）；浅蓝斜纹是估算范围，只有下限时末端渐隐。
- 已用额度是蓝色块里的一条深色细条（深色模式为浅色），已用和容量的比例一眼可见。
- 还没估出容量的进行中周期画成虚线框，写「估算中」。
- 点数不再画在横条上：横条下方单独一个橙色标签「点数 N · $x.xx」，写点数数量和它自己的 API 价格。右侧写「已用 / 容量」和额度的 API 价格。
- 展开明细分为额度（容量、范围、已用、额度 API 价格）、点数（数量和点数 API 价格，用过才显示）和周期信息；图例同步更新。账号详情的「状态」新增「本周期点数」。
- 颜色兼顾浅色和深色主题：蓝色容量、深色/浅色已用、橙色点数，色觉差异下也能区分。

**周期 API 价格不再包含点数**

- v0.5.2 中，周期的 API 价格（`api_cost_usd`）把额度用满后由点数支付的请求也算了进去。现在它只统计额度内的请求，点数请求的 API 价格只在 `over_api_usd` 中。容量和已用额度本来就不含点数，不受影响。

**升级与验证**

- usage 数据库自动升级至 schema v20：对 v0.5.2 写入的周期记录（已有点数拆分，即 `over_api_usd` 不为空），从周期 API 价格中减去点数部分，结果不小于 0。v0.5.2 之前结束的周期没有拆分信息，保持原值，可能仍含点数。升级只执行一次，不重算容量。
- 升级前请停止服务并备份 usage 数据库及相关 WAL 文件。安装与镜像标签说明见[部署指南](https://github.com/Seia-Yurizono/ciallopa/blob/main/docs/DEPLOYMENT.md#image-tags-and-upgrades)。
- 周期 API 价格和 v20 升级各先用失败的测试复现，全部使用合成数据。合并后的完整本地回归 607 项通过，严格 Clippy、Node 状态检查、lock-check、cargo audit 和指纹检查通过；桌面 1280 与 402×874 手机尺寸、浅色和深色截图已检查。

本版本处理账号额度用满后上游继续扣点数的情况：路由优先换到还有额度的账号，额度估算不再被点数请求带偏，并新增手动重置估算。用词上，「额度」指订阅包含的额度（单位 credits），「点数」指另外购买的点数。

**路由**

- 某个额度窗口已满（100%）的账号只在其他账号都没有额度时才用，不论 `quota_avoid_threshold` 是否开启；新会话和已绑定的会话都会换到还有额度的账号，所有账号都满时保持原样。
- WebSocket 会话在下一轮开始时离开已满的账号：可以重放的轮次直接换号重连，带 `previous_response_id` 的轮次以 1012 关闭，由 Codex 重放；记录为 `quota_full`（面板：额度已满，换号重放）。

**额度估算**

- 窗口已满后发出的请求由点数支付，不再计入本周期已用额度，单独记为点数（`over_credits`，按购买点数倍率 Fast 2×、Ultrafast 6×）和对应 API 价格；周期 API 价格仍是总额。
- Plus 只有 5h 满时，周窗口也不动，这段请求不计入周窗口估算。
- 99.5% 以上的快照只表示“至少已满”，不再参与区间计算；连续相同百分比的快照合并后再做相邻斜率回退。
- 记录上游返回的点数状态（`x-codex-credits-*` 响应头和 `/wham/usage`），`/usage/v1/quota` 新增 `quota.credits`；只有余额变化时每个账号最多 60 秒写一次，且变化需达到 1 点数与 1% 中的较大值。

**重置估算**

- 账号详情的「额度周期」右上角新增「重置估算…」，确认后从现在起重新统计当前窗口或这个账号的所有窗口。旧周期归档变灰、不删除，请求记录和费用不受影响，30 天内可以撤销。
- 新增 `POST /admin/v1/accounts/{id}/quota-estimate/reset` 和 `.../reset/{epoch}/undo`，写入经 usage 写入队列。

**管理页面**

- 额度周期改为每个周期一行横条：所有行共用一条 credits 刻度，外框是估算容量，蓝色是已用额度，橙色斜纹是超出后用的点数；右侧写已用 / 容量和 `$API 价格 · 点数 N`，点开一行看全部数值，不依赖悬停提示。还没估出容量的进行中周期显示「估算中」。
- 账号列表和详情在额度旁显示点数余额（「点数 812.5」「点数 不限」「无点数」）。
- 手机上从账号详情打开的确认框（更新令牌、删除、重置估算）不再被详情面板挡住。

**升级与验证**

- usage 数据库自动升级至 schema v19：`quota_obs` 新增 `cr_flags`、`cr_balance`，`quota_cycle_estimates` 新增 `over_credits`、`over_api_usd`，新增 `quota_est_epochs` 表。只增加可空列和新表，不重算历史周期；旧周期如果被点数请求带偏，可以用「重置估算」从现在重新开始。
- 升级前请停止服务并备份 usage 数据库及相关 WAL 文件。安装与镜像标签说明见[部署指南](https://github.com/Seia-Yurizono/ciallopa/blob/main/docs/DEPLOYMENT.md#image-tags-and-upgrades)。
- 每个修复先用失败的测试复现（点数请求抬高用量、满额快照、Plus 周窗口、相同百分比、路由三种情况、WebSocket 换号），全部使用合成数据。合并后的完整本地回归 605 项通过，严格 Clippy、Node 状态检查、lock-check、cargo audit 和指纹检查通过；桌面 1280 与 402×874 手机尺寸、浅色和深色截图已检查。
- 本次未进行真实模型上游验收。发布提交的完整检查、双架构安装包与容器冒烟由标签工作流执行。

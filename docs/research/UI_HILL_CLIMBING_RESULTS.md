## 方法与实际顺序

依据 [Theo 原帖](https://x.com/theo/status/2114955695434993702) 与
[来源核对及执行方法](UI_HILL_CLIMBING.md)，实际执行了：固定案例与基线 → 分模型发现问题、
修正并独立复验 → 保存正确性检查点 → 全新上下文精简 → 独立全量复验及最后局部修正。

Claude 提供方不可用，经用户授权，主阶段采用 **Terra high → Sol high → Astra xhigh**。
精简实现另起 Astra xhigh 上下文，最终全量评价又是新的 Astra 上下文；最后一处小文案由
新 Terra high 复验。每次评审均使用新代理上下文，没有把当前实现者的自行检查当作独立评审。

原帖优化工具描述与上下文，本实验优化 UI；复现的是反馈环与阶段顺序，不是原模型、性能数字
或“删除一半界面”的目标。后几轮局部修正仅复验受影响路径，阶段门槛合并明确标注来源的证据。

## 保留的改动

- 窄屏请求区常显账号、模型、密钥范围筛选；保留独立的“更多筛选”入口。
- 指标按宽度调整列数；缓存率、上游率和关键数值完整显示。
- 详情锁定背景滚动，响应头/体保持可读高度；关闭后恢复原记录焦点与阅读位置。
- 有主要动作的手机请求行给原因与按钮独立空间；额度导航避开固定时间栏。
- 账号窄屏姓名、额度、编辑控件分行；设置和账号页准确区分“配置只读”与允许运行操作。
- 设置校验关联中文字段与范围；放弃草稿使用无倒计时确认，默认取消，恢复字段焦点并按需滚入可见区。
- 内存区默认摘要化；完整指标与历史趋势一步展开，刷新保持开合及焦点，阈值文字警告在折叠时仍可见。
- 缓冲及 WS 上限为 0 时明确标注“不限”；未知、无权限和读取失败不显示虚假健康状态。

## 限制与后续建议

演示使用合成数据，重启与滚动时间窗会改变时间、记录 ID、RSS 和计数；比较的是相同 UI 状态的
布局与操作，不是完全同数据的逐像素实验。没有真实手机触控、软键盘或屏幕阅读器覆盖。
hot/unlimited/error 是本机只读 API 夹具，验证界面条件分支，不代表真实内存压力或限流测试。

两项非阻断建议保留为后续任务：无尝试数据时的“尝试链”名称可更准确；320px 的次要额度时效、
重置时间和长模型尾部仍会省略。核心数值、动作和焦点已验证可达，不将这些建议改写为已修复。

本次不同模型确实补出了此前漏掉的缺陷；由于代码、案例覆盖和数据随轮次变化，不能据此推断
模型能力排名。日常小改可先定点手测、新上下文复核，再在阶段末完整走查；无需每次都重复全部模型。

## 复用与证据

实验当时使用已安装的 Rust stable 1.99.1；仓库固定的 1.95.0 当时未安装，显式 `+stable` 解决工具链选择，
不是单纯修改 PATH。浏览器依赖放在用户目录，通过私有库路径与本地字体运行，无需 sudo，未修改 `.zshrc`。
v0.2.5 发布准备时已安装固定的 Rust 1.95.0，并用它执行发布检查。
`sudo env "PATH=$PATH" t3 browser setup` 保留调用者 PATH 以找到工具，但系统依赖/权限工作不会因写入 `.zshrc` 而消失。

```sh
cargo +stable run --locked -p ciallopa --example ui_demo -- 127.0.0.1:8399
```

浏览器打开 `/ui`，合成管理密钥 `sk-demo-0123456789abcdef`。`UI_DEMO_READONLY=1` 提供配置只读模式。
修改嵌入 HTML 后需重新构建。原始证据目录：`/tmp/ciallopa-theo-experiment-88vwgtx_`，包括
各轮报告/截图、protocol、ledger、各模型 gate、`correctness/` 回退检查点、`source-11/` 最终源码哈希及 `final-gate.json`。
这些临时文件适合当前会话审计；本页及结果附件保存在仓库文档中。

构建通过；既有 UI、设置、账号状态检查在对应改动阶段通过；最后一处文案修正后 UI 状态检查和相关文件
`git diff --check` 通过。仅维护必要 DOM stub 和已有文案期望，未增加自动测试用例。原有上游弃用警告未在本任务扩大处理。

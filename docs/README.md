## 演进方向

当前保持单二进制、模块化单体、本地 SQLite 和内嵌管理页。Codex 是首要客户端；
OpenCode 的本地契约已验证，真实后端支持仍须独立验收。供应商中立是方向，当前上游适配器仍为 Codex。

下一步由实际需求选择：代表性 Linux/TLS 持续混合负载、第二真实上游、首次跨版本状态迁移，
以及具体排障需要的尝试链。框架迁移、分布式控制面、完整 tracing 平台没有预设实施计划。
真实模型验证需要单独的凭据与授权；本地测试使用假上游。

文档只保留现行契约、可复现的方法和有来源的研究结论；阶段日志、临时目录清单和重复验收记录
不作为项目文档维护。新增能力同步更新相应主题，避免再叠加一份“本轮完成”报告。

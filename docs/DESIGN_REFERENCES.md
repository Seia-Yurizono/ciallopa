## 对当前界面的观察

源码阅读范围为 `ui.html`、`accounts.html`、`settings.html` 及 UI 审视文档；阅读时 `ui.html` 正在演进，以下建议不声称所有功能已经落地。使用独立浏览器标签、虚构演示密钥观察了 `localhost:8439/ui` 的旧编译 demo，没有调用真实账号或上游。

旧 demo 在 1280×800 下，“最近请求”从文档 y≈869 开始；390×844 下从 y≈1498 开始。手机首屏几乎全部用于额度。这是任务排序的问题：用户来找一次请求，却需要先穿过额度矩阵、汇总和趋势。现有三页导航、浅色背景、低饱和状态色、自包含资源、手机底部导航都可以保留。

## 八项具体建议

### 1. 三页导航保持简单，概览先通往请求

保留“概览 / 账号 / 设置”，暂不增加组织、工作区、应用、环境等空层级。概览顺序建议为：简短标题与当前范围 → 安静的摘要 → 一张可切换指标的趋势 → 请求列表 → 按需展开的用量分布、账号额度。首屏应能识别“能不能用、最近用了多少、从哪里查请求”。

页面可以用“最近的调用与用量”这样一句短描述提供方向，不需要欢迎大横幅。额度异常可以在摘要处给出“1 个账号需要重新登录 → 查看账号”；完整额度矩阵仍可查看。账号页是添加、恢复、调整账号的地方，概览不必重复其全部操作。

### 2. 六个指标可以保留，视觉权重必须低于任务

六组摘要是容量上限，不应成为六张大卡片。桌面放在同一安静区域，每组一个主值和一句必要说明；删除“请求 114 / 共 114 条”一类重复。首输出、费用等必须保留单位和必要的限定词，长口径可进入帮助说明。少样本、缺价格、取消和未完成不能为追求简洁混进“正常”。

趋势一次展示一个指标，保留单位、时间范围和必要图例；点击时间桶进入对应请求。避免多坐标轴和同时常驻请求、Token、费用三张图。若要再增加指标，优先替换或按需展开，而不是扩展首屏高度。

视觉上优先用留白、字重和表面对比形成层次：正文建议以 14px 为可读基线，区标题约 16px；等宽字体仅给 ID、代码和需要逐字比较的内容。沿用中性背景、小圆角、轻分隔；一个低饱和强调色用于选中或主要入口，错误和警告继续专用状态色。轻松感来自秩序与呼吸空间，不要求渐变、发光、装饰插画或全黑大屏。

### 3. 全局范围与请求条件分两层，并始终说明作用对象

全局范围适合时间、账号、模型、密钥、实例，统一作用于摘要、趋势、分布和请求。请求局部条件适合结果、错误来源、错误码、重试、档位。保留这种分层，但标题使用直白文字，如“查看范围”“仅筛选请求”。当前账号可用性和上游额度是当前快照，不会因为历史时间范围而回到过去，应明确标注。

默认只露出时间、已应用条件摘要、筛选入口；较少使用的输入按需展开。每个已生效条件应可看见、可单独移除，手机同样如此。点图表后，列表附近显示“查看 10:00–11:00 的请求”和返回完整范围入口；不能只悄悄改变列表。深链恢复的相对时间继续滚动，固定时间链接保持不变，两种语义要写清。

### 4. 每条请求都能查看，详情先回答发生了什么

成功请求同样需要元数据详情、记录 ID 和链接。详情第一层为最终结果、时间、请求/实际模型、账号、首输出、总耗时、Token；第二层为尝试过程和错误原因；原始 JSON 按需展开或复制。没有记录正文、没有上游 ID、没有首输出测量应显示“未记录/未知”，不能制造完整响应的印象。

记录 ID 查找入口值得保留，但它是高级直达入口，视觉上不应强过列表标题和常用筛选。区分网关记录 ID、入口 Request ID、上游 Request ID；显示系统真实具备的身份，不混用名称。链接打开失败时区分无权限、未找到、已过保留期等能确定的情形，不确定时不要推断原因。

整行可点击是便利，不应只把 `tr` 改成按钮来承担全部键盘操作。优先在时间或 ID 处提供真正的详情链接/按钮，再扩展行点击；保留表格语义、文字选择、嵌套复制操作。关闭详情后恢复原焦点、滚动位置、筛选与已加载页数。

### 5. 详情侧栏是后续选项，本轮先把现有对话框做完整

Vercel 的右侧栏、Linear 的列表分栏都适合连续查看相邻记录：列表和选中项同时可见。但它们需要明确的选中状态、响应式宽度、键盘导航和独立滚动。它们不能证明本项目立刻重写共享对话框机制就更好。

当前请求详情对话框可以先完善加载/失败/重试、关闭恢复上下文、复制链接和前后记录导航；后一项以确有连续巡阅需求为前提。原始 JSON 不要把主要身份和错误摘要推到下方。若未来做侧栏，只给请求详情独立实现：桌面保证剩余列表仍可用，窄屏用接近全屏的详情页或面板。重置卡、删除、停用最后账号等确认仍保留专注的确认对话框，不共享成一个可并行操作的检查器。

### 6. 空态和异常都给出一个可信的下一步

区分“尚无请求”“当前筛选没有匹配”“日志已关闭”“没有权限”“读取失败”“保留期外”。筛选为空时显示当前条件和清除入口；尚无账号时提供添加入口；读取失败时保留上次成功数据，注明时间并提供重试。状态色必须有文字含义，不能只留一个红点。

持续刷新失败应落在对应区域，不要每轮叠加 toast。整个页面的“更新于”不能让某个失败区块看起来也已更新。浏览历史或详情时保持稳定；用户主动“返回最新”。若后端暂时无法低成本计算新记录数，只显示“返回最新”，不要伪造“新增 N 条”。

### 7. 账号与设置按任务组织，给细节留入口

账号列表保持主体；“添加账号”是明确的主要入口，设备码与文件导入在进入添加流程后再选择。当前首屏常驻的设备码卡片、JSON 大输入框可收起，避免少量账号时也像配置控制台。账号行保留状态与额度，权重、优先级、危险动作放到所属账号的操作区域。

设置保留分类与搜索，先呈现常用任务的自然语言名称；配置键名作为辅助信息。不要把开发者友好误解为隐藏全部技术细节。修改后的未保存提示、差异检查、冲突保留草稿是体验基础；当前草稿保护问题应优先于表单换肤。价格更新、密钥创建、配置重载各有独立状态和结果，避免一次刷新覆盖不相关编辑。

### 8. 手机减少步骤与内容，而非仅缩小桌面

保留底部三页导航。时间、当前筛选摘要、最新/历史状态在手机上可见，更多条件用一个“筛选 N”入口展开；URL 带来的条件不能因 `.d-only` 消失。六组摘要若占三行，应去掉重复副文案，并实际检查请求入口是否又被推到多屏之后；必要时把次要指标放到“更多用量”。

请求保留两行布局：时间/结果/耗时，账号/模型；点开详情看其他字段。主要触摸目标约 40–44px，复制与关闭按钮不能挤进同一条过宽标题。图表时间桶须有触摸、键盘的等价入口，或提供可操作的紧凑时间列表。验收要包括桌面分享链接在手机恢复筛选，而不仅是没有横向溢出。

## 对本轮方向的判断

| 方向 | 判断 | 需要控制的负担 |
| --- | --- | --- |
| 全局 scope + 列表钻取 | 保留，能建立一致的调查上下文 | 全局条件与请求局部条件必须清楚；当前账号/额度快照不假装受历史时间范围约束。 |
| 六组指标 | 有条件保留 | 一行低权重摘要，不继续扩展大卡片；手机依实际高度取舍，不机械复制全部副值。 |
| 图表单指标切换 | 保留 | 单位随指标更新；时间桶操作可发现且可用键盘；请求列表紧接其后。 |
| 所有行都有详情 | 优先落实 | 成功也能查看元数据；可点击整行不能破坏表格语义、选字和复制。 |
| 记录 ID 深链 | 优先落实 | 身份名称准确；链接保留范围；ID 查找保持次级，不能把普通访问者逼进 ID 工作流。 |
| 详情 drawer | 以后按需要推进 | 先修完整性和上下文恢复；不把现有危险确认改成非模态、不为样式改造全局机制。 |

验收重点是完成任务所需的时间和步骤：打开某次失败、看懂当前范围、从详情回到原列表、手机恢复分享链接、读懂无数据与读取失败的区别。没有必要用“图表数量”“卡片数量”来证明界面更成熟。

## 第三轮实测与账号读取修正

2026-10-23，重新构建的虚构 demo，独立浏览器标签，桌面 1280×800 与手机 375×812。实际浏览概览、账号、设置，操作范围仅为查询、筛选、请求详情和虚构账号的读取；未调用真实账号或上游，也没有在本轮改动设置草稿。

- 概览保持摘要 → 单指标趋势 → 请求的任务顺序。手机六组摘要为两行三列，“当前转发 0 / 64 · WS 连接 0”只占一行；请求标题约在文档 y=717、首条约 y=811。桌面请求表宽度 1230px，容器内没有横向溢出。手机仍需一次自然滚动才能开始浏览请求，但已不再先穿过多屏额度面板。
- 时间范围、按需展开的筛选和 ID 查找、失败请求详情之间能连续操作；无匹配时提供清除筛选入口，清除后恢复结果。详情按钮触摸高度约 40px，长标题没有挤出屏幕。三页在 375px 宽度下均无页面横向溢出。设置搜索无匹配有明确空态，搜索“转发”能定位相关配置。
- 账号页发现并复现了真实状态问题：仅额度与重置卡读取返回 503 时，账号主体成功，但旧额度被清空且全页时间显示刚刚更新。修正后各来源独立替换成功快照；普通失败保留已有数据并展示该来源上次读取时间，首次失败明确“暂无成功数据”，403/404 清除对应缓存并说明无权限或接口不可用。页头改为“账号更新于”，避免暗示所有来源均已更新。
- 账号修复另用独立 8441 虚构 demo 验证：双 503 后 Alice 的 11% / 23% 保持；额度 403 与重置卡 404 后只清除这两项，主体账号仍可读；退出后重新进入的首次 503 不再沿用旧快照；恢复正常读取后额度恢复且提示消失。局部提示在 375px 内换行，无横向溢出。实际源码提取的 Node 检查覆盖独立恢复、旧请求晚到及跨登录身份隔离。

本轮未发现需要新增导航层级、额外指标卡或改成全局侧栏的理由。优先保持信息层次和失败状态可信；手机“自动”刷新开关的可见文字已补入源码，其文案没有作为这次构建实测的证据。

## 添加账号与设备码流程收敛

同日后续以最新源码重建独立 8441 demo，实际检查 1280×800 与 375×812。账号标题旁保留一键“导入文件”，增加明确的“添加账号”入口；设备码区域在标题下原地展开，JSON 粘贴内容使用原生折叠区。默认列表不再常驻两张添加表单，空账号直接提供添加按钮。展开时焦点进入设备码开始按钮，收起后返回入口；收起仅折叠界面，不中断进行中的登录。手机修正空表格单元格占满整行，隐藏无账号时无关的权重提示。

设备码检查先用实际源码回归复现：开始请求在退出后才返回，会把旧代码写入下次登录。修复为每次流程绑定当前身份与代次，开始请求和轮询均在异步返回后核对；停止等待、退出、成功或失败均清除一次性代码、链接与计时，退出额外清除粘贴内容。轮询不重叠，旧请求结束不能恢复新流程按钮或触发新身份退出。

服务端目前没有撤销设备授权的接口，因此操作明确命名为“停止等待”，并说明“停止等待后，仍可在浏览器完成授权；账号可能随后加入”。浏览器用拦截的虚构 device 响应验证了停止后旧轮询晚到、同一密钥退出重登后旧开始请求晚到、503 后原位按 Enter 重试，以及成功结束后的清理；没有实际发起设备授权或调用真实账号。两个尺寸下添加、粘贴、流程提示均无横向溢出。

## 钻取后的上下文可见性

随后重建demo复核请求卡：概况115条业务请求，另有1条预热；点击请求数后的列表也是115条，
结果下拉明确显示“业务请求（不含预热）”，刷新URL和继续翻页保留该条件。
真实页面同时暴露一个定位问题：原有滚动把请求标题放在视口顶端，恰被置顶导航和范围栏遮住。
现在按范围栏的实际高度留出滚动间距；1280px下请求标题在置顶区域下约12px，375px固定时间范围
换行时仍保留同样间距。时间桶钻取也沿用该定位，选中时段、返回入口与筛选保持可见，焦点落在结果筛选。
这次只补定位和已有DOM桩所需属性，以真实浏览器确认布局，没有为滚动效果加入测试框架。
